# 勉たんからNotionのベンケイへ記入

移行中も現在のNotion記入を維持し、勉たんのベンケイ画面からも同じ原文へ記入できるようにする。現時点は工藤の個人認証だけが利用可能。ホームの一覧は閲覧・確認用、専用ページの「ベンケイに書く」を展開して記入する。

保存はNotionのベンケイ上部に1件の共有連絡を作り、同じブロックIDの内容を勉たんへ反映する。Notionから直接変更した本文は既存の2分同期で取り込む。勉たんで作った連絡は勉たんからも編集できる。既存の任意形式のNotion投稿・進捗表・埋込DB・動画を一括して編集できる段階ではない。これらは原文へ戻る導線を維持する。

## 操作結果と復旧

入力、保存結果、直前に保存した本文は確認できるよう残す。操作IDを保持し、同じ操作の再送で二重投稿しない。Notionへ書き込んだか不明な場合は自動再送をせず、原文の対応リンクで結果を照合する。結果が見つからなければ不明のまま保持し、新しい操作として同内容を重複させない。

Notionで本文が変わっている場合は保存直前に比較して競合とし、入力を保持する。子ブロックが追加される等の構成変更があれば既存原文を壊さず、原文での編集へ案内する。Notion APIの更新は原本側の同時編集を原子的にロックする方式ではないため、移行期間の並行編集では直前の版照合と保存後の読取確認を行い、自動マージはしない。

対象ページの差込位置が変わった場合は推測して別の場所へ書かない。Notionの文字数・rich_text件数・UTF-8ペイロードの制限を保存前に検査する。保存のために本文を切り捨てない。

## 検証・運用

`node scripts/benkei-authoring-admin.mjs --schema --apply` で専用outboxと対応付けを追加する。既存職員設定は変更しない。一般利用者・未認証からのDB直接アクセスを拒否する。既存の共有原文・個人の確認履歴は別テーブルのまま維持する。

隔離DBと偽Notionで、容量・作成と取込・同IDの重複防止・応答喪失後の原本照合・編集競合・原本構造保護・期限切れ操作の再送禁止を検証した。ブラウザでは保存結果と本文の保持、不明結果の原本確認、同IDでの明示再開をAPIモックで検証する。実際のNotionへのテスト投稿・テスト編集はしていない。実業務の試用を終えて正式公開済みとはしない。

APIは `/api/staff/benkei-authoring`。本文記入と、読了確認・本人の一覧から外す操作は独立している。旧運用からの全業務移行については `docs/parallel-migration-policy.md` の業務別台帳へ記録を続ける。

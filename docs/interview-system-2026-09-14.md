# 面談予定・入力システム

2026-09-14。ユーザーは「面談の入力システムを完成させる」を目標とし、必要な調査・実装・検証・反映を許可。変更前のバックアップと最終報告を必須とする。読み取りの確認は不要。

**公開制限（2026-09-14追加指示）**：生徒のスマートフォンにはまだ表示させない。職員向けとして実装・検証を続け、生徒・保護者画面やLINEメニューへ面談の入口・予定を追加しない。生徒向け公開は別途明示指示を受けるまで行わない。

**利用者限定（同日追加）**：工藤・金城だけがスマホから利用できるようにする。認証済み職員コード `KUDO` / `KINJO` のみ面談API（一覧・登録・履歴・同期）を許可。管理者ロールだけでは許可しない。専用入口 `/staff/interviews?staff=KUDO` と `?staff=KINJO` は利用者選択を補完するだけで、既存職員パスワードが必要。PCでも同じ制限を適用し、端末判定による抜け道を作らない。

## 実装した範囲

- `/staff/interviews`。既存の職員認証を使用し、登録・承認・変更・取消は事務部・正社員・管理者に限定。
- 登録済み授業から職員用の「予約可」を算出。担任・校舎の入力補完、任意日時の手動登録、枠の非公開・復元、設定変更。
- 面談45分＋予備15分、通常13時以降。18:35～20:05は5分刻みで開始時刻を選び、最大1件。20:30・21:30の夜枠。
- 授業・担当・生徒・指定教室の重複確認、保存直前のDB版確認、操作番号による再試行の重複防止、履歴保持。
- 実施済みへの変更、記録の下書き・編集・確定、確定後の理由付き訂正。
- 面談記録は予定から日時・参加者・目的を補完し、実際の日時・参加者を別に保存。内容・決定事項・職員の対応・家庭への依頼・次回確認日・自由メモを入力できる。空の下書きも保存可、確定には内容と実績が必要。フォーム版を記録に保持する。面談APIのみ上限64KBとして日本語5000字を受け付ける。
- 生徒台帳に面談用の不変IDを追加し、別テーブルの既存IDを保持。台帳追加・番号変更・Notionページ変更にDBトリガーで自動追従。既存の氏名・番号等は変更しない。
- トップとサイドメニューに入口を追加。他の既存画面の構成は変更しない。

## 現在の制限と続き

- **統合設計全体の完成ではない。** 生徒・保護者の予約画面、希望順位・キャンセル待ち・通知、Zoom会議の自動作成等はこの職員入力画面にまだ接続していない。LINE送信・全生徒への公開は行っていない。
- **NotionのベンスケDBが参照不可。** 既存設定のDBに対し、接続「塾業務システム連携」はHTTP 404。環境設定・保存済みトークン・既存同期設定から別経路も調査したが参照できない。削除済みとは断定しない。本人権限で同DBへのコネクト追加が必要。
- Notion反映処理は実装・模擬API検証済みだが、実DBのスキーマ照合・設定・実反映は未実施。未接続の間は画面で明示し、職員が既存予定を確認した後だけ承認できる。
- 接続回復後は実際の項目と選択肢を取得し、予約ID・不変生徒ID等を既存運用へ影響させず準備し、`interview_settings.notion_source_id`を設定して実データで検証する。現在のマッピングを実スキーマ確認なしで有効化しない。
- Notion側で変更・削除されたカードは上書きせず確認対象にする。差分選択・復元・既存カード紐づけの画面、既存Notion予定からの重複検査、自動枠のNotion登録は未実装。
- 面談記録は現在勉たん内だけに保存。Notion面談DBへの記録同期、担当講師本人の編集権限・限定公開・記録自動保存・目的別フォーム等は未完了。
- 生徒IDの初期関連付けは本番380件。台帳削除時も面談履歴と最後の番号・Notionページを保持し、再利用番号には新しいIDを発行する。不変IDの書換え・再利用は拒否する。既存の他機能の外部キーが学籍番号変更を制限する場合は、その制約を維持する。氏名の上書きだけでは同姓同名・別人の入替えを判定できないため、生徒の入替えに既存台帳行の上書きを使わない。

## 検証と復帰

- `npm run test:interviews`：時間枠、重複、入力、DB版競合、冪等性、権限、記録修正、同期不明結果、Notion機密情報除外の検証。
- `tests/browser/interviews.spec.ts`：入力補完・保存前確認、ログイン制限、一般講師の操作制限、390px表示。
- 既存ファイルは指定の `scripts/backup-before-edit.ps1` で同じフォルダにバックアップ済み。
- 本番DB適用：`node scripts/apply-interviews-schema.mjs --env ../../.env.local --apply`。既存面談DBへのID追従追加は `--identity-only` を付ける。適用前JSON（生徒台帳・面談データ・関数・台帳列とトリガー）は作業用clone内の `analysis_outputs/interview-deployment/`。個人情報を含むのでGitへ追加しない。
- 復帰時は該当コードのコミットをrevertして再デプロイする。追加列・トリガーは旧画面とも互換があるため残し、入力済み予定や監査履歴を削除しない。トリガー自体を戻す必要がある場合は書込みを停止して保存済みの関数・トリガー定義から復元し、復旧期間中に追加された生徒のIDを再照合する。
- 作業場所：親フォルダの `analysis_outputs/interview-system-20260914/`。親本体の古いcheckout・未コミット変更と独立子リポジトリは変更していない。

# LINE予約画面の操作点検と戻る導線（2026-09-16）

## 対象と変更

LINEの個別入口から使う面談・自習室、そこから到達する検証用メニューと職員の予約管理を点検した。

- 面談の登録・変更・状態変更・記録・設定・Notion差分・履歴・保存確認に、スクロールしても見える「← 戻る」を追加。
- 保存確認から一つ前の入力へ戻る場合、生徒、日時、メモ、確認チェック、設定、記録をReact stateに保持。編集画面から一覧へ戻る場合は従来の「閉じる」と同じ終了操作。
- 同時に表示するダイアログは一つ。Tabキーの移動を画面内に制限し、Escapeも同じ戻る操作とする。背景のスクロールを止める。
- 通信結果不明時の再試行が入力ダイアログの裏に隠れていたため、現在のダイアログ内にも表示。保存結果を確認するまで入力・戻るを無効化し、同じ操作番号で再試行する。
- 自習室に「日時・席の選択に戻る」「予約状況に戻る」「入力を再開する」を追加。画面内の往復では利用日・時間帯・座席を保持。
- 座席図から時間帯へ戻るボタンとフォーカス移動を追加。複数時間帯の説明は折りたたみ、主要な説明を短くした。
- 予約メニュー／自習室管理から来た場合のみ、その入口へ戻るリンクを表示。戻り先は列挙した内部画面に限定し、任意のURLは受け取らない。
- 旧面談検証画面から実際の面談予定へ戻るリンクを追加。旧面談の確認にも共通の戻るUIを使用。

## 操作確認表

| 流れ | 確認・改善 |
|---|---|
| LINE専用入口→面談／自習室 | 既存の認証方式を保持。本番反映後に両職員で確認する |
| 面談の新規入力→確認→入力 | 上部の戻る、メモとチェック保持、戻るだけでは書き込みなし |
| 面談の変更→確認→変更入力 | 変更理由、Notion確認チェック、入力値を保持 |
| 承認・見送り・取消 | 状態変更→確認→状態変更。理由を保持し一覧にも戻れる |
| 実施済み・記録入力 | 記録→確認→記録。実際の保存と再表示も既存テストで確認 |
| 予約枠の設定 | 設定→確認→設定。設定値を保持 |
| Notion差分取り込み | 差分→確認→差分。確認後にだけ書き込み |
| 変更履歴 | 上部から一覧に戻る |
| 面談の通信切断 | 同じ操作番号で再試行。結果不明の間は戻る・編集を停止 |
| 自習室の日付・時間・席 | 同じ画面で修正。席から時間へスクロール・フォーカス移動 |
| 自習室の内容確認 | 一つ前に戻っても選択保持 |
| 自習室の別日時入力 | 予約状況へ戻る→入力を再開。選択保持 |
| 自習室の申請→承認→取消 | 既存の共有状態更新、承認反映、取消を確認 |
| 自習室の状態取得障害 | 復旧後に最新状態へ自動回復 |
| 職員代理申請・取消 | 検索・選択・確認・取消、競合、通信切断、同一操作の再確認 |
| 来室・退室 | 入力→確認→保存、再試行、版管理、権限、ログイン切れ |
| 予約メニュー→自習室→メニュー | 明示したリンクで戻る |
| 旧面談の第1〜第3希望 | 確認から戻ったとき希望日時・相談内容を保持。承認・取消も確認 |
| 旧面談の職員確認→実面談 | 職員コードを保持して戻る |
| 未認証・権限外 | 個人情報や承認操作を表示しない |

## 検証

- 型チェック、対象ESLint、隔離出力先の本番ビルド成功。
- 関連ブラウザ45ケースを確認。最初の実行で古いタイトル期待値・Codex未モック・新規試験のモック漏れを検出。現在の明示的なタイトルとCodex権限拒否のモックへ修正し、44件と残り1件の再実行が成功。
- Windows上のPlaywrightは各試験の結果が出た後、webServer終了待ちが戻らないためCtrl-Cで停止。テスト結果と終了処理は区別する。
- スマホ390px、座席一覧320px、スクロール後の戻るボタン、入力保持、通信結果不明時の再確認を検証。
- ブラウザ試験は架空データ。実際のLINEアプリ内ブラウザの端末固有動作は未検証。
- 本番で自習室は引き続き検証用JSON。面談は実DB・Notion予定連携。今回、DB構造・予約ルール・通知仕様は変更していない。

本番反映と疎通結果はルート `docs/next-session.md` の最新記録を参照。

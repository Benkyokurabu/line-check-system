## 初回範囲と入退室の運用保留

- 自習室予約とQR・学籍番号による塾全体の来塾/帰宅記録を統合する実装範囲は維持する。
- 入退室は使える状態まで整えるが、当面使わない。機能を無効にし、打刻受付・保護者通知を開始しない。隠した画面のURLやAPIを直接呼んでも保留中の処理が動かないことを検証する。
- 運用開始を保留したため、「初回から本校・南教室の両方で使うか」という質問は現在の回答待ちから外す。運用開始前に対象校舎・端末・通知先を確認する。
- 自習室そのものは本校だけ。事務部による自習室の来室・退室確認と、塾全体の打刻は区別する。

入退室の統合可否と当面の運用保留は聞き直さない。保留は実装対象からの除外ではなく、実際の打刻・通知を開始しないという意味である。

## 予約の入口と本人・保護者

- 予約の入口はLINE。本人がLINEを使えない場合は、保護者による申請に対応することが決定済み。
- 紙の初回ログイン案内を必須とする前提は採用しない。既存の確認済みLINE・生徒・続柄の紐づけを生かし、入力された学籍番号だけで他人の予約・取消を許可しない。
- 本校の生徒と確認済みの保護者はリッチメニューから予約画面を開く。南教室だけの利用者には予約メニューを表示せず、例外利用は個別LINE連絡を受けた職員が同じ在庫へ代理登録する。南教室の施設利用自体を禁止する意味ではない。全員向け正式公開は未実施。2026-09-05、ユーザーの明示依頼により指定アカウント1件だけへ表示確認用メニューを設定済みで、遷移先は予約登録を行わない `/self-study-room/menu-preview`。
- 共通の予約対象権限判定を `src/lib/reservation-access.mjs` に追加。確認済みの本人・母・父・保護者の紐づけのみ許可し、未確認・解除済み・別家庭・曖昧な重複を拒否する9件の単体テストを追加した。

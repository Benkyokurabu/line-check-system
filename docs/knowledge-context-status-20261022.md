# 根拠付き知識基盤の到達点

既存資料を正本のまま参照し、分類済み知識の保存・検索・訂正履歴・出典更新時の再確認を行うローカル共通処理を追加した。Node標準機能で動作し、CLIとES moduleの両方から利用できる。

`knowledge/context-store.mjs` が保存と取得、`knowledge/cli.mjs` がCLI、`knowledge/context-store.test.mjs` が訂正・範囲・競合・原文更新等の18件の試験を提供する。新しい専用CIは標準Nodeだけで試験を実行する。既存アプリの画面・API・本番設定は変更しない。

通常検索は最新revisionを選んでから文字列を照合する。古い説明だけに一致しても旧版を現在の知識として返さない。引用、出典全体のハッシュ、確認日、適用期間、校舎・学年・役割・個別対象を保持する。出典が変更された・読めない場合は要再確認となり、現在の判断基準から外す。事例や改善案・推測を全体ルールへ自動で格上げしない。保存は期待版照合・排他・ファイル置換を使い、競合と誤編集を検出する。

業務の私的な知識データは `資料集約/知識基盤/` へ保存し、公開Gitに含めない。実際の業務記録への登録と索引更新は、既存の資料集約とローカルの再開メモに残す。この公開記録と架空例には個人情報を含めない。

画面とAI処理への自動接続、職員別の閲覧制御、サーバー側の私的保存、外部原資料の自動取得・更新監視は未実装。ローカルの明示的な検索利用と、常に自動で参照される状態を区別する。複数PCからOneDriveへ同時保存する分散運用には対応していない。

[保存形式・コマンド・復旧の説明](../knowledge/README.md)、[PCとスマートフォンで操作できる説明HTML](knowledge-context.html)。HTMLの3タブ、訂正・更新の3状態、キーボード操作、1280pxと390pxの横はみ出し・ブラウザエラーを確認した。

検証：専用Node試験18件成功、関連ESLint成功、TypeScriptの型検査成功。最新mainを土台に依存関係を用意し、標準のNext.js Turbopack本番ビルドを `.next-staff-test` へ分離して成功した。業務知識8件の出典ハッシュを確認し、全件不変。公開差分は共通処理・架空例・説明・専用CI・私的データの除外設定のみ。

# 面談資料の毎日自動作成

Notionベンケイで本人・先生・日時を判定できた未実施の面談を、既存の主担当・予備PCが作成する。ブラウザを開いておく必要はない。毎日の実行時刻と本日から何日先まで作るかはDB設定で管理する。

## 動作

- どちらか1台のPCが電源ON、Windowsログイン済みで、Excel・NAS・インターネットを使用できる必要がある。主担当が停止中なら予備が巡回から保存まで処理する。
- 定刻に両方OFFの場合は、当日の起動後に未完了の巡回を実行する。面談時刻を過ぎた予定は依頼作成時・作成開始時・保存直前に除外する。
- Notionの要確認予定は作成せず、状況に表示する。最新アンケートが複数同日時で特定できない場合も失敗として表示する。
- 手動の資料作成依頼を優先する。自動依頼は待ち時間が10分を超えても処理する。失敗は5分後に最大3回まで再試行する。
- 自動処理はheartbeatで `daily-offline-v1` 対応を登録したPCだけが担当する。旧版主担当を更新する前でも、新版の予備PCは自動作成を担当でき、旧版PCは手動依頼だけを取得する。
- 面談予定、原文、最新回答、原本ファイルのサイズ・更新日時、テンプレートを比較する。変更がなく、保存済みファイルのSHA256が一致する場合はPDF再作成を省略する。
- 指導簿を含む選択資料がそろわない場合は資料名付きのエラーを表示し、資料を黙って省かない。元から存在しない任意個人成績票や志望校資料は未取得として表示する。
- 保存直前に予定・最新アンケート・面談原文・本人情報・原本・ジョブ権限を再確認する。変更・取消は以前の資料を保持し、当日の巡回状況に表示する。

## 保存先と安全な更新

`\\TS3210\benko\03 教務部\015 各面談行事／文化会館も含む\98面談資料` の既存の先生・学年・日時生徒フォルダを使用する。生徒フォルダの **面談資料.html** を開く。

一式を `_auto_versions/版ID/` に保存して全ファイルを確認した後、表紙HTMLだけを原子的に切り替える。HTML内のbase URLからその版のPDFと原文を読むため、更新途中に新旧のPDFが混ざらない。旧版は保持する。先生が追加したファイルを削除・更新しない。

ブラウザ保存済みの資料も、保存情報の本人・面談予定が一致し、生成元テンプレートとHTMLが一致する場合は旧一式を保全したうえで同じフォルダに更新する。本人・面談を確認できない資料、先生が編集したHTMLや自動管理ファイルは上書きを保留する。元の固定PDFはそのまま保持し、最新版は表紙HTMLから開く。

AI要約は保存時点で完成しているものを含める。未完成でも面談記録と生徒情報の原文を必ず保存し、後日の巡回で完成した要約を含む版へ更新する。

## 本番反映の順序

1. `node scripts/configure-interview-material-daily.mjs --env 本番envファイル` でロールバック検証する。
2. `--apply --disable` でスキーマを適用する。**daily_key列を使用するため、サイトの新コードより先にDBへ適用する。**
3. 型チェック・lint・関連テスト・ビルド後にコードをmainへpushし、Vercelと本番バージョンを確認する。
4. `local_helper/build-daily-release.ps1` で補助アプリを作成する。主担当/予備それぞれの既存設定を保持し、バックアップ後にexeと最新export-guide.ps1を配布・設置する。PC専用worker.jsonは交換・再発行しない。
5. 自動作成を止めた状態で2台の接続、NAS、指導簿、HTML版切替を確認する。
6. 実行時刻・対象期間の決定後、`node scripts/configure-interview-material-daily.mjs --env 本番envファイル --apply --enable --time HH:MM --days 日数` で有効化する。停止は `--apply --disable`。

初期状態は `enabled=false`。時刻と範囲が未決定のままタイマーを有効にしない。実際の保存先や個人情報、workerの秘密値をGitへ入れない。

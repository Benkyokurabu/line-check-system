# 卒塾生の連絡先・自習室利用

2026-09-07：授業用 `student_roster` と継続保管する `student_registry` を分離。
既存の授業対象は `current_roster`（在塾/見学中を推測で区別しない）、卒塾者は `卒塾`。
自習室資格は `study_room_eligibilities.enabled`。有効期限・許可者の項目は設けない。

## 適用と確認

- `node scripts/apply-student-registry-schema.mjs`：非公開バックアップを保存し、トランザクションで移行と既存データ不変を検証してロールバック。
- `node scripts/apply-student-registry-schema.mjs --apply`：同じ検証の成功時のみ確定。
- `npm run test:roster`：隔離DBで登録、監査失敗時の全体ロールバック、再適用、重複防止、授業非混入を検証。
- 新規DBは既存schemaとLINE本人確認migrationを適用した後、`student_registry_20260907.sql` を適用する。過去のLINE migrationを再適用すると旧FK/関数に戻る可能性があるため、最後に本migrationを再適用する。

## 限定登録

`register_study_room_former_student(jsonb,text,text,text)` はサービス権限だけで実行可能。
Notion等で識別子・氏名・学年・校舎・卒塾状態を照合し、LINEの一意性と既存紐付けを確認した上で、明示依頼の根拠 `user_instruction` を記録する。
人物台帳、自習室資格、sharedアカウント、表示名、監査履歴を同一トランザクションで保存する。
架空のLINEメッセージは使わない。既存の本人確認根拠や主連絡先は更新しない。
完全一致の再実行は変更なし。異なる既存登録は上書きせずエラーとする。

授業用名簿には卒塾者を追加しない。既存の出欠候補・授業一覧は従来の名簿を使い続ける。
現在対象の通常同期は台帳へ反映するが、卒塾者の授業名簿への再追加は明示的な在籍調整が必要として拒否する。
連絡先の登録済み一覧は台帳から氏名を表示し、詳細に卒塾・自習室利用可を表示する。
一般公開の人物検索APIは追加しない。未登録卒塾生の追加はサービス権限による上記の限定登録経路で扱う。

## 自習室オンライン受付との区別

資格の保存はオンライン予約の有効化ではない。現在旧APIは停止中。
新しい自習室ワークフローの本番適用時に、人物台帳へのFK/検索接続と資格チェックを各申請・承認で実施し、shared申請者を本人・保護者と断定しない。
新ワークフローの認証接続・DB適用・受付開始は別工程。今回の人物台帳migrationで予約受付を有効化しない。

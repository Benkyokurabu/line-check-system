# ベンケイの共有確認

工藤先生の確認用として `/staff/benkei` とホームの共有欄を追加。Notionベンケイ上部の共有連絡を同期する。本人が確認しても行はその場に残り、確認済みの状態と結果を表示する。左のチェックで選び、明示ボタンで自分の確認一覧から外す。全件タブには残り、取り消して一覧へ戻せる。対象者ごとの確認時刻・版別履歴を表示する。閲覧のみでは確認済みにしない。投稿者も自動確認にしない。

## 原本と確認の整合

共有連絡はNotionブロックIDで識別し、本文とリンクのSHAが変わると新版になる。編集日時だけの変更では新版にしない。確認直前にNotion原文を再取得し、変わっていれば新版を保存して409、取得失敗なら503で確認を付けない。既存の確認履歴は削除しない。個人の一覧除外も版ごとなので、新版は再表示される。未確認の項目を除外する操作はサーバーでも拒否する。完全同期時だけ原本から消えた共有連絡を非表示にする。部分取得や取得失敗で消さない。

同期範囲はベンケイの最初の区切り線より上の共有連絡、先頭の単元テスト進捗パネルを除く。現在の原本では7件。下部の学籍・タスク等の埋込DB、動画の内容、リンク先の本文までは読了確認の対象ではない。リンク先は原本へ戻って確認する。全Notion検索・原文の収集状況は別の `/staff/school-context` で扱う。

## 認証と対象者

既存職員認証と同一オリジン検査を使用。専用テーブルとRPCはservice_role以外の直接アクセスを拒否。既存の有効な職員名ディレクトリ21名を確認対象者として登録し、管理者と先生ログインが同一人物の場合は明確な対応付けだけを使用する。現在は工藤先生の人物IDだけが利用可能で、他の先生への正式公開はしていない。

`bentan_benkei_settings.trial_only` を解除することは正式公開の状態変更になる。試用結果を確認するまで解除しない。確認対象者一覧の登録と、全員が操作できる設定を混同しない。

## 運用

`node scripts/benkei-admin.mjs --schema --apply` は専用スキーマと対象者を登録する。既存の職員設定は変更しない。`--sync` は読取と件数確認、`--sync --apply` は原本の同期、デプロイ後の `--schedule --apply` は専用2分ごとの同期ジョブを登録する。既存の別ジョブや秘密値を変更しない。CLIは接続情報をローカル設定から読み、原文や秘密値を出力しない。

## 検証と次の提案

隔離PostgreSQL互換DBで本人だけの確認・版変更で再表示・重複確認の冪等性・他人の未確認維持・非公開権限を検証。UIは390px/1280px、開くだけではPOSTなし、改訂409と再確認、全件で確認者履歴、未認証/権限外を確認する。

ユーザーの追加指摘「消えると確認し直しにくい」を受け、常設一覧への入口、ホームの最近確認した連絡、専用検索・保存済み、担当業務の完了管理を追加提案している。現在実装済みの全件タブ・履歴と、これらの追加提案を区別する。私的な調査資料は親の `資料集約/ベンケイと業務支援AI_他社調査と提案_2026-10-22.md` に保存する。

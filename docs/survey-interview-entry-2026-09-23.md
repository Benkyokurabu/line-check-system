# 秋アンケートから面談を打診する

2026-09-23。トップの「2026年 秋のアンケート」に「アンケートから選ぶ」を追加。同じボタンを職員面談画面にも置く。

ログイン済みの職員は再ログインせず、対象アンケートと自分の担当・提出済みを初期表示する。担任・提出状況・進捗の絞り込みは職員ごとにブラウザへ保持。回答原文の表示可能なプロパティと原本リンク、過去回答を確認できる。照合が曖昧な回答を他生徒へ紐づけない。

各生徒の「日程を打診する」→担任の候補日時→内容と宛先の確認→LINE送信→打診履歴へ進む。未打診、回答待ち、承認待ち、確定、再調整、送信要確認をアンケート提出状況とは分ける。有効な打診があれば既存履歴に誘導する。承認待ちは既存の職員承認画面へ接続。

送信結果が不明な場合は同じ操作番号で再確認する。送信結果の受領後に一覧取得だけ失敗しても、送信結果を保持して更新エラーを併記。打診保存済みを誤って「予約確定済み」と表示していた通知エラー文言も修正。

回の識別子は2026-autumn、表示名は2026年 秋のアンケート。既存の2026-09-09開始分と明示的に対応させた。新規の打診だけ、既存slots JSONの追加メタデータに回ID・名称を記録する。既存履歴にアンケート情報を推定付与しない。DBスキーマ変更は不要。新メタデータを含む作成・再送・保護者回答・承認を隔離DBで検証。

## 公開・実装範囲

現行の工藤のみの検証用送信制限、オンライン45分、回答期限（最初の面談日の前日まで）は維持。新画面は一般家庭への送信・権限拡大を行わない。金城の直接URLでも送信UIとAPIへの呼出を許可しない。一般公開はこれまでの明示的な保留を維持する。

画面案にある全家庭の通知先、一般講師の打診権限、複数の面談方法、一括打診、職員間で共有する下書き、2日前期限への統一は今回有効化していない。保護者の回答・職員の承認・Notion反映・確定LINEは既存経路を利用する。打診元の回答ページの版そのものの永続スナップショットも今回の回ID記録とは別。

変更前バックアップはscripts/backup-before-edit.ps1で実施。ローカルの面談関連81テスト、型チェック、関連lint、ビルドを確認。画面試験はPC・390pxで、入口、既存ログイン、回答表示、送信前確認、制限対象、二重打診の抑止、応答不明の再確認、一覧取得失敗、保護者の既存経路を確認。実LINE送信や予約変更を伴わない検証を使用。
